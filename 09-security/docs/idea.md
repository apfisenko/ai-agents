Идея — **автономный ReAct-агент банковского обслуживания в Telegram**: ведёт диалог, сам решает, когда опираться на **локальную базу документов**, и при необходимости вызывает поиск по ней как **инструмент** (`rag_search`), а не полагается на «общие знания» без привязки к текстам.

**Предметная область (содержание ответов):** справочные материалы по банковским продуктам и условиям из файлов в каталоге `data/` — в частности потребительский кредит (PDF), условия по вкладам (PDF) и выгрузка справочных текстов (JSON). Дополнительно агент может вызывать **MCP-инструменты** отдельного сервиса **`mcp-bank-agent`** (см. [vision.md](vision.md)): **`search_products`** — выборочный поиск по **динамическому** справочнику продуктов банка (вклады, кредиты, карты, счета и т.д. по типам, названиям, условиям, акциям и типовым параметрам), когда нужных сведений нет или мало в PDF/JSON в `data/`; **`currency_converter_mcp`** — **актуальные** курсы и конвертация через онлайн-сервис (официальные данные ЦБ РФ в обёртке API — в vision); **`loan_payment_mcp`** — ориентировочный расчёт **аннуитетного** платежа и переплаты по параметрам сумма / ставка (% годовых) / срок в месяцах (упрощённая модель, не оферта и не текст договора); **`open_credit_card`** — **эмуляция** открытия кредитной карты (мок на стороне MCP: логирует факт вызова и возвращает агенту реквизиты «выпущенной» карты; контракт и политика отображения — в vision); **`open_deposit`** — **эмуляция** открытия вклада (мок MCP по сумме, сроку в месяцах и годовой ставке; упрощённая оценка начислений — в vision). Перед фактическим вызовом **`open_credit_card`** или **`open_deposit`** пользователь в Telegram **подтверждает или отклоняет** операцию (**human-in-the-loop**, только Accept / Reject — без редактирования параметров). Тон, ограничения и роль консультанта задаются **системным промптом** с явными правилами: **когда вызывать** `rag_search` и **`search_products`**, **`convert_currency`** и **`currency_converter_mcp`**, **`loan_payment_mcp`**, **`open_credit_card`**, **`open_deposit`**, **few-shot** примеры и подсказки по формулировке поисковых запросов. Факты из документов по возможности **привязываются к найденным фрагментам** (RAG); сведения из `search_products` и расчёт из `loan_payment_mcp` — с кратким указанием источника/дисклеймером в ответе, без подмены юридически значимого текста из PDF.

**Безопасность и злоупотребления (продуктово):** снижение риска утечки персональных и платёжных данных за счёт **маскирования PII** в том, что видит пользователь в чате (в т.ч. номера платёжных карт: включение через **`MASK_PAN_OUTGOING`**, см. [vision.md](vision.md)); в **типовых логах** приложения — не подставлять полный PAN в открытом виде. Ограничение частоты (**rate limiting**) на уровне чата: по **текстовым сообщениям** — **`TELEGRAM_TEXT_RATE_LIMIT_ENABLED`** (**`false`** — без лимита; порог окна см. **`TELEGRAM_TEXT_RATE_LIMIT_WINDOW_SECONDS`** / **`TELEGRAM_TEXT_RATE_LIMIT_MAX_MESSAGES`**); отдельно по **обращениям к графу агента** (**`ainvoke_turn`**) — **`AGENT_INVOCATIONS_RATE_LIMIT_ENABLED`**, **`WINDOW_AGENT_SECONDS`**, **`MAX_AGENT_INVOCATIONS_PER_WINDOW`**. Прочее — **[vision.md](vision.md)**.

**Поиск по базе:** за кадром используются те же режимы retrieval, что и ранее (**semantic**, **hybrid** семантика + BM25, **hybrid_rerank** с cross-encoder), переключаемые конфигурацией. Отдельный узел **трансформации запроса по истории перед retrieval** в продуктовом потоке **не нужен**: формулировки для `rag_search` **генерирует сам агент**.

Дополнительно — **прозрачность ответов** (показ использованных документов и страниц при `SHOW_SOURCES`), **наблюдаемость** (LangSmith) и **оценка качества RAG** (RAGAS на датасетах), при этом пайплайн оценки должен получать **полный перечень документов, использованных при ответе** (в т.ч. полный текст чанков для метрик).

По запросу пользователя агент может вызывать **локальный** инструмент **`convert_currency`** для приблизительного пересчёта без обязательного запуска MCP-сервера (тот же класс дисклеймеров, что в vision). Если нужен **текущий** курс на момент запроса и конвертация «как у котировок ЦБ» — **`currency_converter_mcp`** (при доступном MCP). Для ориентировочного платежа по кредиту при заданных численно сумме, ставке (% годовых) и сроке в месяцах — **`loan_payment_mcp`** (при доступном MCP), с дисклеймером, что модель упрощённая. Если MCP недоступен — **`loan_payment_mcp`**, **`open_credit_card`** и **`open_deposit`** недоступны; не подменять расчётом «с потолка» официальный график банка, опираться на **`rag_search`** по документам и честные ограничения; открытие карты или вклада через MCP не эмулировать локальными заглушками вне сервера. Если сбой MCP или сервер не запущен — остаётся **`convert_currency`** и работа без MCP-инструментов (**graceful degradation** — в vision).

Техническая реализация, стек, команды бота и границы scope — в [vision.md](vision.md). Здесь зафиксирована только продуктовая концепция.
