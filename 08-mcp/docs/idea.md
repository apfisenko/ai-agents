Идея — **автономный ReAct-агент банковского обслуживания в Telegram**: ведёт диалог, сам решает, когда опираться на **локальную базу документов**, и при необходимости вызывает поиск по ней как **инструмент** (`rag_search`), а не полагается на «общие знания» без привязки к текстам.

**Предметная область (содержание ответов):** справочные материалы по банковским продуктам и условиям из файлов в каталоге `data/` — в частности потребительский кредит (PDF), условия по вкладам (PDF) и выгрузка справочных текстов (JSON). Дополнительно агент может вызывать **MCP-инструменты** отдельного сервиса **`mcp-bank-agent`** (см. [vision.md](vision.md)): **`search_products`** — выборочный поиск по **динамическому** справочнику продуктов банка (вклады, кредиты, карты, счета и т.д. по типам, названиям, условиям, акциям и типовым параметрам), когда нужных сведений нет или мало в PDF/JSON в `data/`; **`currency_converter_mcp`** — **актуальные** курсы и конвертация через онлайн-сервис (официальные данные ЦБ РФ в обёртке API — в vision). Тон, ограничения и роль консультанта задаются **системным промптом** с явными правилами: **когда вызывать** `rag_search` и **`search_products`**, **`convert_currency`** и **`currency_converter_mcp`**, **few-shot** примеры и подсказки по формулировке поисковых запросов. Факты из документов по возможности **привязываются к найденным фрагментам** (RAG); сведения из `search_products` — к краткому указанию источника в ответе, без подмены юридически значимого текста из PDF.

**Поиск по базе:** за кадром используются те же режимы retrieval, что и ранее (**semantic**, **hybrid** семантика + BM25, **hybrid_rerank** с cross-encoder), переключаемые конфигурацией. Отдельный узел **трансформации запроса по истории перед retrieval** в продуктовом потоке **не нужен**: формулировки для `rag_search` **генерирует сам агент**.

Дополнительно — **прозрачность ответов** (показ использованных документов и страниц при `SHOW_SOURCES`), **наблюдаемость** (LangSmith) и **оценка качества RAG** (RAGAS на датасетах), при этом пайплайн оценки должен получать **полный перечень документов, использованных при ответе** (в т.ч. полный текст чанков для метрик).

По запросу пользователя агент может вызывать **локальный** инструмент **`convert_currency`** для приблизительного пересчёта без обязательного запуска MCP-сервера (тот же класс дисклеймеров, что в vision). Если нужен **текущий** курс на момент запроса и конвертация «как у котировок ЦБ» — **`currency_converter_mcp`** (при доступном MCP). Если сбой MCP или сервер не запущен — остаётся **`convert_currency`** и работа без MCP-инструментов (**graceful degradation** — в vision).

Техническая реализация, стек, команды бота и границы scope — в [vision.md](vision.md). Здесь зафиксирована только продуктовая концепция.
